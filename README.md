# Mercury HF modem for Android

Android build of the Rhizomatica Mercury HF modem, version 1.9.17 (git b2ad7863,
2 October 2026). Separate from the Android-Winlink app: the app talks to this
modem only over Mercury's VARA-style TCP ports (control 8400, data 8401 in the
Mercury Modem app; 8300/8301 is Mercury's default and stays in use on the PC), so the app contains no Mercury code.

## Source

`upstream/` is a plain copy of https://github.com/Rhizomatica/mercury at tag
`v1.9.17`, commit `b2ad78631255127b50b368ae6052f5df35e3f20b` (2 October 2026),
without its git history and without 7 ready-made Windows/macOS radio-control
library files under `upstream/radio_io/hamlib-w64/` and `hamlib-macos/` (skipped
by Mercury's own `.gitignore`; the Android build does not use them). The only edits to those files are in
`patches/0001-android.patch`.

To move to a newer Mercury release: replace `upstream/` with a copy of the new
release, apply `patches/0001-android.patch` (adjusting it where Mercury's code
moved), rebuild, and repeat the acoustic tests.

## What is here

| Path | What it is |
|------|------------|
| `upstream/` | Copy of Mercury v1.9.17 (see Source above) with the changes in `patches/` already applied |
| `patches/0001-android.patch` | Changes to Mercury's own files (`audioio/audioio.c`, `data_interfaces/tcp_interfaces.c`), see below |
| `patches/0002-android-sound-device.patch` | Change to Mercury's own files (`audioio/ffaudio/ffaudio/aaudio.c`): a sound device given as a number (`-i` / `-o`) opens that Android audio device (`AAudioStreamBuilder_setDeviceId`); before, the text was only read as a microphone preset name |
| `port/android_port.h`, `port/android_port.c` | Fill Android gaps: `exp10f`, and `shm_open`/`shm_unlink` as plain files in `$MERCURY_SHM_DIR` (default `/data/local/tmp`) |
| `port/ffring_ext.h` | Two ring-buffer readers (`ffring_read_min_begin`, `ffring_read_max_begin`) that `aaudio.c` calls but Mercury's bundled ffbase lacks |
| `gen/web_packed.c` | Generated by `upstream/gui_interface/websocket/pack_web.sh` |
| `CMakeLists.txt` | NDK build of the `mercury` command-line program, arm64 |

### Change to `upstream/audioio/audioio.c`

1. Every `defined(__linux__)` became `(defined(__linux__) && !defined(__ANDROID__))`.
   Android also defines `__linux__`, so the ALSA/PulseAudio branches were taken
   and Mercury's existing Android branches were never reached.
2. Added the missing AAudio branch to `radio_playback_thread` and
   `radio_capture_thread` (40 ms buffer).
3. Device listing: AAudio in ffaudio cannot enumerate devices. Listing now
   prints that the system default device is used, instead of crashing.

### Change to `upstream/data_interfaces/tcp_interfaces.c`

On Android the control, data and broadcast ports listen on 127.0.0.1 only,
so other devices on the phone's network cannot connect and make it transmit.

## App build (PC, Git Bash, this folder)

`local.properties` (not in the repository) must name the Android SDK, e.g.
`sdk.dir=C\:/Users/Robert/AppData/Local/Android/Sdk`, with NDK 28.2.13676358
and CMake 3.22.1 installed in it.

```bash
./gradlew.bat assembleDebug assembleRelease
```

The Gradle build runs the CMake build above, strips the program and packs it
as `lib/arm64-v8a/libmercury.so`. The service starts it with
`-x aaudio -p <control port> -b <broadcast port> [-i <input device ID>] [-o <output device ID>] -L <files>/mercury.log`,
`HOME=<files>`, `MERCURY_SHM_DIR=<cache>`, working folder `<files>` (where it writes `mercury.ini`
with `[audio] tx_delay_ms`), and stops it with SIGTERM.

Known upstream detail, left unchanged: in ffaudio `aaudio.c` `on_play`, the
zero-fill on underrun never runs (`n < d1.len + d2.len` is never true). Mercury
plays silence when idle, so this only matters if the playback thread falls behind.

## Settings (2026-10-07)

On the app screen, under **Settings**, saved with **Save settings**, used at the next **Start**:

| Field | Mercury setting | Default |
|---|---|---|
| **Control port (1024 to 65534; data port is the next number)** | `-p` (data port = control + 1) | 8400 (data 8401) |
| **Broadcast port (1024 to 65535)** | `-b` | 8102 (Mercury's own default 8100 is the Dire Wolf Modem app's AGW port) |
| **Sound input (receive)** / **Sound output (transmit)** | `-i` / `-o` with the Android audio device ID (patch 0002), or nothing for "Phone's default" | Phone's default |
| **TX delay before sound, ms (0 to 2000; default 150)** | `[audio] tx_delay_ms` in `mercury.ini` | 150 (Mercury's own default is 10) |
| **Mercury options** (2026-10-09), under headings **Speed ladder and link** (13), **Busy-channel detector** (5), **Sound** (TX gain, capture channel), **TNC (the program driving Mercury)** (2) | `[arq]`, `[channel]`, `[audio] tx_gain_db`, `[main] capture_channel`, `[tnc]` in `mercury.ini` | Mercury 1.9.17's defaults; each field shows its range (the limits Mercury's `cfg_utils.c` accepts; the two link timeouts 1 to 3,600 s) |

**Restore defaults** puts the TX delay (150 ms) and all 22 Mercury options back to their defaults and saves; the ports and sound devices are not changed. Checked on the phone 2026-10-09: TX gain -2.5, capture channel right and IAMALIVE 30 s were written to `mercury.ini`; Mercury sent IAMALIVE every 30 s on the control port (it read the file); **Restore defaults** set them back. Mercury's other options (screen and web UI, its own PTT and Hamlib, log detail, chat store, sound system) are left out: not usable or not needed on the phone. Release APK 736,606 bytes unsigned (732,650 before).

A sound device is saved by ID and name; at Start a device that is no longer present is looked up by name (a re-plugged USB sound card gets a new ID), else the phone's default is used and the log says so. Checks on save: ports in range, the broadcast port different from the control and data ports, TX delay 0 to 2000 ms. FieldMail's **Mercury control port** (Mercury session screen) must match the control port.

PTT: this app keys no radio. FieldMail keys it from Mercury's "PTT ON" / "PTT OFF" lines on the control port. The 150 ms TX delay gives it time: measured from Mercury's "PTT ON" to the USB serial RTS line on, 4 to 94 ms.
